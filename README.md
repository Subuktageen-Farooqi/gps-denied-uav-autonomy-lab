# GPS-Denied UAV Tracking & Predictive Standoff Pursuit

**Custom Edge Vision · Kalman Estimation · Confidence-Aware Autonomy · Predictive Standoff · A\* Planning**

A simulation-only aerial autonomy portfolio project combining noisy relative perception, target-state estimation, target-loss prediction, autonomous state transitions, obstacle-aware navigation, custom YOLO detection, and an NVIDIA Jetson Orin NX deployment path.

> [!IMPORTANT]
> This project demonstrates safe-standoff observation in a 2D kinematic simulation. It does not implement terminal interception, collision pursuit, weapon control, or real-aircraft control.

## UI preview

### Autonomy Lab

The interactive 3D view animates the UAV, target, Kalman estimate, detections, predicted position, standoff radius, and randomized obstacles. Altitude is a visualization layer; autonomy dynamics remain 2D.

![Autonomy Lab showing animated pursuit, obstacles, and telemetry](docs/screenshots/autonomy_lab.png)

### Perception telemetry

The Perception Lab runs `.pt`, `.onnx`, or `.engine` models on uploaded images and videos and reports measured latency. Monocular range is explicitly marked unavailable.

![Perception Lab backend and measured latency cards](docs/screenshots/perception_lab_.png)

## Features

- Four deterministic tracking scenarios with configurable field dimensions
- Seeded random obstacle placement, shape, footprint, and height
- Noisy relative detections with random and scheduled dropouts
- Constant-velocity Kalman filter with prediction through occlusion
- `SEARCH → ACQUIRE → TRACK → PREDICT → REACQUIRE` autonomy FSM
- GPS-denied following and predictive safe-standoff pursuit
- Inflated-grid, 8-connected A\* planning without diagonal corner cutting
- Animated 3D Streamlit visualization and quantitative run analytics
- Lazy-loaded Ultralytics detector for image/video inference
- Optional ByteTrack IDs and calibrated azimuth/elevation observations
- Dataset auditing, custom YOLO training, validation, and model manifests
- Actual mAP, precision, recall, F1, confusion matrix, PR curves, and TP/FP/FN examples
- Empirical YOLO reliability-profile bridge into the metric simulation
- ONNX export plus Jetson Orin NX TensorRT build and benchmark tools

## Architecture

The real-vision and metric-simulation paths are intentionally separate. Bounding-box pixels are never treated as metric coordinates.

```text
Training / deployment

Labeled UAV dataset → Dataset audit → YOLO fine-tuning → Validation
                                                       ↓
                                   best.pt → ONNX → Jetson TensorRT FP16

Vision runtime

Camera frame → YOLO → bbox / class / confidence → ByteTrack
                                                ↓
                                  Camera intrinsics → bearing
                                  Range: unavailable (monocular)

Closed-loop simulation

YOLO evaluation → empirical reliability profile
                              ↓
Simulated metric detection → Kalman filter → autonomy FSM
                                          ↓
                     predictive standoff goal → A* → UAV simulator
```

Ground-truth target state is restricted to simulator internals, simulated sensor generation, visualization, and evaluation. Autonomy and planning consume only detections and estimated state.

## Enable YOLO on an NVIDIA GPU

Install a CUDA-enabled PyTorch build using the command generated by the official [PyTorch installation selector](https://pytorch.org/get-started/locally/). Install PyTorch before the optional vision requirements so the intended CUDA build remains selected.

```powershell
python -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements-vision.txt
```

Verify that PyTorch sees the GPU:

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CUDA unavailable')"
```

Always launch Streamlit through the same Python environment:

```powershell
python -m streamlit run app.py
```

This prevents a system `streamlit` executable from accidentally using a different, CPU-only Python installation.

## Use existing UAV weights

Place compatible Ultralytics weights in `models/`:

```text
models/
└── drone-detector.pt
```

Open **Perception Lab**, select the model, upload an image/video, configure confidence and IoU, and select **Run perception**. The adapter accepts common target labels: `uav`, `drone`, and `quadcopter`.

Recommended starting values:

| Setting | Value |
|---|---:|
| Confidence | `0.20` |
| IoU | `0.55` |
| Resolution | `640` |
| Video tracking | Enabled |

Public `.pt` files are serialized model artifacts. Use sources you trust and verify published hashes before loading them.

## Prepare a custom dataset

Export annotations in **YOLO26** format. YOLO11/YOLOv8 normalized detection labels use the same essential text layout, but YOLO26 matches the default training command.

```text
datasets/uav/
├── dataset.yaml
├── images/
│   ├── train/
│   ├── val/
│   └── test/
└── labels/
    ├── train/
    ├── val/
    └── test/
```

Each label row is `class_id center_x center_y width height`, with coordinates normalized to `[0, 1]`. Empty label files are valid hard-negative examples.

Example `dataset.yaml`:

```yaml
path: datasets/uav
train: images/train
val: images/val
test: images/test

names:
  0: uav
```

Audit before training:

```powershell
python -m training.dataset_audit --data datasets/uav/dataset.yaml
```

The audit reports missing/corrupt files, invalid boxes, class distribution, image sizes, bbox-area distribution, hard negatives, duplicates, and small-object proportion.

## Train on RTX 3060 12 GB

Training starts only when this command is explicitly run:

```powershell
python -m training.train `
  --data datasets/uav/dataset.yaml `
  --model yolo26n.pt `
  --epochs 50 `
  --imgsz 640 `
  --batch auto `
  --device 0 `
  --seed 7
```

The default is YOLO26n transfer learning. If the installed Ultralytics release cannot load YOLO26n, the script reports the issue and explicitly falls back to YOLO11n. Reduce the batch size if GPU memory is exhausted.

## Evaluate the detector

```powershell
python -m training.evaluate `
  --model artifacts/models/uav_yolo26n_640/weights/best.pt `
  --data datasets/uav/dataset.yaml `
  --imgsz 640 `
  --device 0 `
  --output artifacts/models/uav_yolo26n_640
```

Open **Model Evaluation** in the dashboard to view these outputs. If an event does not occur—for example, zero false positives—its example remains explicitly unavailable.

## Create a detector reliability profile

```powershell
python -m perception.detector_profile `
  --csv frame_results.csv `
  --model uav_yolo26n_640 `
  --output artifacts/perception_profile.json
```

Select **YOLO-derived detector profile** in Autonomy Lab to let measured detection availability, confidence, and dropout behavior influence closed-loop simulation. This remains a metric simulation; pixel coordinates are not converted into fake range.

## ONNX and Jetson Orin NX deployment

Export portable ONNX on the workstation:

```powershell
python -m deployment.jetson_orin_nx.export_onnx `
  --model artifacts/models/uav_yolo26n_640/weights/best.pt `
  --sample path/to/validation-image.jpg
```

Build and benchmark on the target Jetson:

```bash
python -m deployment.jetson_orin_nx.build_tensorrt \
  --model best.onnx \
  --precision fp16

python -m deployment.jetson_orin_nx.benchmark \
  --model artifacts/edge/jetson_orin_nx/model_fp16.engine \
  --source path/to/validation-video.mp4
```

TensorRT `.engine` files are device/runtime-specific. A desktop RTX-built engine is not presented as a production Orin NX engine. INT8 requires representative calibration data and post-quantization accuracy validation.

## Limitations

- 2D kinematic autonomy model; altitude is visual only
- Simulated metric perception for the closed-loop autonomy demo
- Monocular YOLO provides bearing but not metric range
- No aerodynamic flight dynamics, VIO, SLAM, or flight-controller integration
- No real Jetson performance claim until benchmarked on the target
- No real-aircraft validation
